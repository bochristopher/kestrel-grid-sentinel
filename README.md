# Kestrel Grid Sentinel

A web prototype for the 2026 NASA International Space Apps Challenge, Mountain View local event.

**Challenge:** [Harmonization of MODIS and VIIRS Hot Spots](https://www.spaceappschallenge.org/2026/challenges/modis-and-viirs-hot-spots/)

**Live demo:** [GitHub Pages](https://bochristopher.github.io/kestrel-grid-sentinel/)

**Project deck (7 slides):** [deck/Kestrel_Grid_Sentinel_SpaceApps2026.pdf](deck/Kestrel_Grid_Sentinel_SpaceApps2026.pdf)

## Summary

Kestrel Grid Sentinel turns NASA FIRMS MODIS and VIIRS active-fire records into one daily burning-activity calendar for California, then ranks transmission-corridor spans for watch. VIIRS pixels are 375 m and MODIS pixels are about 1 km, so raw counts cannot be compared; the tool bins both sensors to a 0.01° daily grid. NASA POWER wind and weather supply spread and flight context. The ranking is meant to task Chargebotic's line-perching drone, **Kestrel**, to the spans that most need persistent eyes.

This is a hackathon decision-support prototype, not an operational dispatch tool. **Kestrel is at TRL 4.** A 5 November 2026 attempt to land on a de-energized line struck the line rather than landing. This project does not claim that Kestrel has perched on an energized line, or that it is deployed for wildfire response.

## NASA datasets

- **NASA FIRMS** [Fire Information for Resource Management System](https://www.earthdata.nasa.gov/data/tools/firms)
  - MODIS Collection 6.1 active fire / hotspots
  - VIIRS 375 m active fire / hotspots from NOAA-20 and NOAA-21 (Suomi NPP is queried; the public 7-day file used in the 15 Nov 2026 build had no detection rows)
- **NASA POWER** [Prediction Of Worldwide Energy Resources](https://power.larc.nasa.gov/) daily wind, temperature, humidity, and precipitation

The prototype uses the public FIRMS 7-day USA CSVs (no MAP_KEY required) and the NASA POWER daily point API.

## How to run the prototype

Python 3.10+ is enough. There are no third-party package requirements.

```bash
python3 build.py
```

Then open `index.html` in a browser. The page has the latest run embedded, so it works from a local file. Map tiles come from OpenStreetMap and need a network connection.

`build.py` pulls the public NASA FIRMS 7-day CSVs for the USA and NASA POWER daily meteorology for a few corridor points. If a fetch fails, it will reuse `data/latest.json` when one exists.

## Honest limits

- This is a hackathon decision-support prototype, not an operational dispatch tool.
- Kestrel is at TRL 4. A 5 November 2026 attempt to land on a de-energized line struck the line rather than landing. Do not describe perching on energized lines, or fire-response deployment, as demonstrated.
- Demo corridor waypoints are geographic sketches for the map, not official utility GIS.
- Harmonization uses a 0.01° (~1 km) daily grid so MODIS and VIIRS counts can be compared. It is not a full radiometric intercalibration of the two sensors.
- The public FIRMS files used here cover about seven days, not the full 20-year archive. A FIRMS MAP_KEY would extend the calendar.

## AI-use disclosure

AI tools helped write the submission text, the prototype code, and the slide outline and deck. A person on the team chose the challenge, set the product facts that could be claimed, and must review every field before any official submission. Live hotspot counts and weather values in the dashboard come from NASA FIRMS and NASA POWER, not from a model. The 0.01° daily-grid method and the span-ranking rules are simple, documented heuristics, not a trained fire-spread or landing model. No generated imagery is presented as a photograph of a test or a NASA scene. No NASA logos appear in AI-made content.
